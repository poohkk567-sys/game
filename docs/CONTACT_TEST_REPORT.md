# ผลตรวจรุ่นปุ่มนั่ง+สกิลและแรงปะทะ

ทดสอบด้วย Godot **4.2.2** และ **4.6.3** บน Linux ใช้ Compatibility renderer / Mesa llvmpipe สำหรับภาพ และ physics/input ของ Godot จริง

| ชุดตรวจ | 4.2.2 | 4.6.3 |
|---|---:|---:|
| `bash tools/check.sh` รวมระบบเดิมและใหม่ | 1,147 ข้อ ผ่าน | 1,147 ข้อ ผ่าน |
| `test_contact_controls.gd` รวมอยู่ในจำนวนข้างบน | 108 ข้อ ผ่าน | 108 ข้อ ผ่าน |
| `test_chord_render.gd` ภาพใหม่ครบทุกเฟรมทั้งสองทิศ | 96 ตัวอย่าง ผ่าน | 96 ตัวอย่าง ผ่าน |

ไม่พบ SCRIPT ERROR, ERROR หรือข้อทดสอบล้มเหลวในการรันชุดสุดท้าย

## ตัวชนและแรงปะทะ

- ตรวจระยะตัวและลำดับซ้าย/ขวาทุกเฟรมระหว่างเดินดัน 60 เฟรม ทั้งหันซ้ายและขวา อีกฝั่งเคลื่อนที่ตามแรง ไม่มีการซ้อนหรือสลับฝั่ง
- วิ่งดันที่ขอบซ้ายและขวา 60 เฟรม ระยะรับแรงยังคงอยู่และไม่ทะลุขอบ
- เป้าหมายถูกล็อกไม่เลื่อนเมื่อโดนเดินดัน
- โจมตีจริงแล้วเกิดตัวสั่น hit pause และตำแหน่งถอยออกจากผู้โจมตีในทิศที่ถูกต้อง ตรวจหมัด เตะ เตะปิดคอมโบ และอัลติ โดยระยะถอยเพิ่มตามน้ำหนักทั้งสองทิศ
- การ์ดแตกยังรับแรงถอยได้แต่เดิน กระโดด ชาร์จไม่ได้ ภาพตัวไม่หายช่วงหยุดภาพกระแทก
- ชุดทดสอบเดิมตรวจดาเมจและคอมโบจริงต่อ รวมฟีโน่ หมัดรัว การ์ด บัฟ และการตีลอย ปรับการรอเฟรมบางจุดให้รวม hit pause ใหม่

## ปุ่มและกติกา

- ส่ง InputEventKey จริงทั้ง P1/P2 ทดสอบสกิลนั่งทั้ง 4 ช่องของทั้งสามตัว ไม่เผลอกระโดด
- ส่ง InputEventJoypadButton จริงจากคนละ device ทดสอบ ลง+X / ลง+A / ลง+B / ลง+RB ทำงานแยกสองฝั่ง
- ทางลัด T/Y/F เดิมไม่ปล่อยสกิลแล้ว ส่วน U และอัลติ I ของ PHUZASHI ยังทำงาน
- เริ่มที่ 50 MP, Blink จ่าย 5, แปลงร่างต่ำกว่า 70 ไม่ได้, จ่าย 70 จาก 100 แล้วเหลือ 30 หลังจบ
- ร่าง ASSJIRO แปลงแล้วใช้สกิลทั้งห้าที่ 0 MP ได้ ไม่เกิดการหัก/คืนมานาผิด และทุกท่ายังมีคูลดาวน์
- พายุแครอทซ่อนภาพคนทั้ง rig และภาพพิเศษ รับดาเมจ กระสุน หรือการล็อกไม่ได้ตลอดท่า หลังจบคืนร่างและรับดาเมจได้ตามปกติ
- มวยไทยใช้ภาพ IDLE/DASH ใหม่ ระยะเคลื่อนที่ต่อเฟรมต่ำกว่า 8px เร่งและผ่อนความเร็ว ระยะรวมอยู่ระหว่าง 70–100px ไม่มีการย้ายตำแหน่งทันที
- อัลติสองฝั่งเข้าคิวคัตอินถูกตัวต่อกัน เกมยังเคลื่อนที่ต่อ และเริ่มยกใหม่ล้างคัตอินกับคิว
- ค่าจอยเก่าเลิกใช้ทางลัดสกิลเดิมแต่คงปุ่มปกติและการจับคู่จอยไว้

## ตรวจภาพ

96 ตัวอย่าง = ฟีโน่คู่ซ้อน 16 เฟรม + ท่ายืน/แดชมวยไทย 16 เฟรม + พายุแครอท 16 เฟรม × 2 ทิศ ไม่พบตัวหายหรือขอบภาพถูกตัด

พบและแก้เศษเท้าจากแถวก่อนหน้าติดเข้ากับภาพมวยไทยระหว่างตรวจในฉากจริง: ใช้กรอบร่างเต็มที่เชื่อมต่อกันแทนการแบ่งช่องเท่ากัน ภาพแดชสุดท้ายไม่มีเศษภาพเหนือหัว

บันทึกภาพและวิดีโอ 1280×720 60 FPS ประมาณ 19 วินาทีจาก Godot 4.6.3 แสดงเดินดัน ติดขอบ หมัด/คอมโบ ฟีโน่คู่ซ้อน ไฟ/ปีศาจม่วง คัตอินครบสามตัว ซีอิ๊ว 70 MP พายุแครอท และท่ายืน/แดชมวยไทย ตรวจฉากเดียวกันใน Godot 4.2.2 ด้วย ตัวสาธิตเติมมานาบางช่วงเพื่อรีวิวท่า เกมจริงเปิดที่ 50

ภาพ PHUZASHI ต้นฉบับยังมี SHA-256:
`d0d6156d5114d612c1d04e39781fcd5c783eb09b0ba1268fc8b42c9779e6be06`

จอยทดสอบด้วยอินพุตจำลอง ยังไม่ได้ลองจอยฮาร์ดแวร์จริงบน Windows การสั่นฮาร์ดแวร์เรียกเฉพาะจอยที่ระบบตรวจพบว่าเชื่อมต่ออยู่

## เปิดตรวจซ้ำ

```sh
bash tools/check.sh
godot --path . --audio-driver Dummy --fixed-fps 60 --script tests/test_chord_render.gd
```

ตั้ง GODOT_BIN เพื่อเลือกเวอร์ชัน engine ไฟล์ `.res` ใหม่สร้างด้วย Godot 4.2.2 ในโปรเจกต์นำเข้าแยก ZIP ซอร์สตรวจ CRC และเทียบข้อมูลทุกไฟล์ มี SHA-256 แยก ไม่มี EXE/PCK/cache วิดีโอแยกดาวน์โหลดเพื่อให้ ZIP มีขนาดเหมาะสม
